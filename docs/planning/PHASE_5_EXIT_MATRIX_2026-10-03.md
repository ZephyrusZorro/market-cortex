## Contracts and lifecycle

`candidate_v1` records instrument identity, symbol, detector/version, outcome/status, event date, horizon/bias, manifest and UTC as-of, market-state ID/regime, source quality/freshness/coverage, every typed condition and evidence reference, supporting/opposing IDs, contradictions, rejection reasons and an evidence hash. Its deterministic ID distinguishes semantic evidence states; an identical state at a later cutoff deduplicates while the first stored payload retains its original cutoff. The entire scan is ephemeral unless `record=true`.

`research_thesis_v1` records the originating and subsequent candidate IDs, version, statement, status, confirmation/invalidation conditions, assumptions, risks, limitations, feature versions, manifest/as-of, optional CORTEX run IDs and a transition history. PostgreSQL row locking serializes version changes. The version table is append-only; only the head's version pointer changes. Monitoring refuses a backwards cutoff, cannot silently reopen `NO_EDGE`, `AVOID`, `INVALIDATED` or owner-held `EVENT_RISK`, and turns a previously `VALID` thesis with broken detector conditions into `INVALIDATED`. Audited owner decisions may set `WATCHING`, `NO_EDGE`, `EVENT_RISK` or `AVOID` with a reason; only deterministic detector evaluation can set `VALID`. The permitted transition table and every detector threshold are documented in [the Phase 5 design](../opportunity/PHASE_5_OPPORTUNITY_AND_THESIS.md).

## Boundaries and Phase 6 readiness

The scanner covers Binance public spot **daily** bars for five USDT pairs. Its market state can be unavailable when data is stale, and no candidate should be read as executable guidance. Daily OHLCV cannot establish intraday quality, order-book sweeps, event causality or institutional accumulation. `liquidity_sweep`, `event_driven` and `accumulation_proxy` are explicitly registered as unsupported. There is no calibrated probability, backtested edge, sizing, portfolio risk approval, broker write path or order placement. Local model inference was unavailable; CORTEX review used its deterministic grounded fallback. Upstox and Alpaca authenticated live validation remains `DEFERRED_NOT_CONFIGURED`; their adapters are preserved, and equity identity mappings and calendars still require verification before use.

Phase 6 can consume the versioned candidate, thesis, contradiction, quality, freshness, volatility, drawdown and market-state evidence as inputs to risk rules. `VALID` remains a detector state and must never itself authorize capital deployment.
