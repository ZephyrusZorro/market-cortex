# Owner-Machine Read-Only Probe Runbook

1. Download and extract the **Phase 0.6 or later repository ZIP** (the Phase 0.5 ZIP does not contain `scripts/probe_sources.py`). Open PowerShell inside its `market-cortex` folder. Verify `Test-Path .\scripts\probe_sources.py` returns `True`. Then run `python scripts/hardware_profile.py --path C:\MarketCortexData --disk-type ssd --output config/hardware.local.json` (change drive/type to actual values). Keep this local report outside Git. Check free bytes and physical cores.
2. Run `python -m pip install -r requirements-probe.txt` for precise US time zone handling on Windows. The script can run without it using a conservative UTC fallback that is labeled in the report. Copy `config/owner.example.yaml` to `config/owner.yaml`; fill base currency, timezone, enabled markets, primary storage budget, separate `backup_location`, market data budget, AI model budget and three cloud/privacy flags. Do not put API keys or passwords in YAML. This file is gitignored.
3. If you have Upstox and/or Alpaca credentials, set them **locally in process environment** (`UPSTOX_ACCESS_TOKEN`; `APCA_API_KEY_ID` and `APCA_API_SECRET_KEY`) through a local keychain or temporary shell session. Set `ALPACA_TRADING_ENV=live` only if the keys belong to a live Alpaca trading API account; the default is `paper`. This selects a **read-only asset lookup host** and never enables order calls. Do not paste them into chat, command-line arguments, reports or Git. Binance public market-data checks need no key. The script only makes GET requests to fixed provider hosts; no trading endpoints.
4. From the `market-cortex` root in PowerShell, run `python scripts\probe_sources.py --run --output data\probes\phase_0_6_local.json`. The output directory is created automatically. If `python` launches a different installation, use the full path to your Python executable. Limit is six NSE, five US and five crypto candidates, with small historical samples. The report excludes credentials and raw response bodies; it is gitignored. Review each HTTP status. Account access is established only when an endpoint succeeds; one successful symbol never proves the whole market.
5. Inspect oldest **sampled** timestamp, latest **complete** daily candle, venue and native IDs, IEX historical access and the separate SIP historical sample (neither proves real-time SIP entitlement), UTC/session format and AAPL/NVDA raw versus split sample. Probe output deliberately does **not** claim full historical depth, dividend semantics, private caching permission or prolonged reliability. For an exact history start, run a separate bounded backfill/page scan after confirming the account tier; document requests and data gaps.
6. If Binance is unavailable from that machine, use the documented Coinbase public product/candle GET endpoints as a separate manual fallback probe. If Upstox or Alpaca fails account eligibility, evaluate Kite Connect or another licensed US source with the same small checklist. Never merge exchange histories.
7. Send back the **redacted** JSON report, hardware report and nonsecret owner settings if you want this workspace to evaluate readiness. Remove any account identifiers you prefer to keep private; never share credentials. We can update the pilot and source choices from these measured results.
