# API Contracts (Phase 1 read slice)

**Baseline:** [Phase 0 §5](architecture/PHASE_0_BASELINE_2026-09-26.md). [Registry](../packages/contracts/registry.schema.json).

Implemented read routes: `GET /api/v1/health`; `GET /api/v1/instruments?query=...&as_of=...` (mapping candidates and explicit ambiguity); `GET /api/v1/calendars/{venue_id}/sessions?from=...&to=...`; `GET /api/v1/bars?instrument_id=...&interval=P1D&from=...&to=...&as_of=...&manifest_id=...&adjustment_basis=raw&provider_id=...&offset=...&limit=...`; `GET /api/v1/data-health`; `GET /api/v1/manifests/{id}`. The CLI binds to loopback and middleware rejects non-loopback clients. No write or order routes exist. Bars include complete observation envelopes and retain conflicting providers; no silent average. `as_of` is a UTC availability cutoff, and `manifest_id` pins a published dataset. The current API uses offset pagination and a simplified error shape; cursor stability and complete error/coverage taxonomy are not finished. OpenAPI is generated at `/docs`.

Internal `DomainEvent` envelope: `event_id`, `event_type`, `schema_version`, `occurred_at`, `recorded_at`, `aggregate_id`, `correlation_id`, `idempotency_key`, `payload_ref`. `occurred_at` is domain event time; `recorded_at` is commit time. Outbox commits atomically with transactional records and references a committed data manifest; subscribers tolerate duplicates, retries and reordered delivery. Event types are namespaced and versioned; no event contains unconstrained provider payload or owner secrets. A new feed kind adds a payload schema without changing the envelope.
