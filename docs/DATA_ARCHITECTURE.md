# Data Architecture

**Baseline:** [Phase 0 §§5–6](architecture/PHASE_0_BASELINE_2026-09-26.md). [Source matrix](data/DATA_SOURCE_MATRIX.md); [test strategy](TESTING_STRATEGY.md).

Request → immutable source batch (hash, rights/retention) → parse → resolve identity → validate time, units and shape → deduplicate → quarantine or append → publish manifest → derive freshness. Preserve all disagreeing sources. Missing does not mean zero, and provider adjusted OHLC is never silently mixed with raw OHLC. Source correction appends a superseding observation and new manifest. Raw bytes are stored only when rights permit; otherwise keep metadata/hash and an explicit `raw_retention_state`.

Time: UTC instants use RFC 3339 with offset `Z`; local date and IANA zone are separate. Bar window `[start_at,end_at)` is independent of a venue-local `session_date`. Event/published/available/ingested/effective times are distinct; `available_at` is never guessed from the event time. Unknown historical publication means `availability_basis=unknown` and exclude from strict point-in-time replay. Backfills record *first known to this system* at backfill time, not pretend prior availability. A historical market feed may have a documented publication proxy, explicitly marked as such. As-of query filters availability and immutable manifest membership, then resolves supersession only among revisions available at cutoff.

Storage: PostgreSQL owns identity, jobs/outbox, rights and dataset pointer. A versioned manifest lists content hashes, schema version, provider, kind, venue, instrument bucketing, UTC event-date bucket, min/max time, row count, source batch, permissions, previous manifest and validation state. Parquet files are staged, fsynced/hashed, then manifest/pointer committed; readers open the exact committed manifest. Orphan cleanup and hash check are recovery tasks. Phase 1 can use instrument + event year/month partition for bars; a future tick/depth writer may adopt venue/kind/day/hour while the manifest/catalog and query interface stay stable. Avoid one file per symbol per day; compact only through new immutable manifests.

Freshness: per kind/provider/venue/calendar publication SLA. Dashboard distinguishes market closed, feed delayed, pipeline failed and truly absent. A stale fallback remains labeled. Budget and retention apply before storing third-party bytes. Backup PostgreSQL consistent dump plus exact referenced artifacts/manifests/config (excluding secrets) with encryption and hashes; restore to isolated location, verify foreign keys, pointers, checksums and an as-of sample. Backup is not complete until a rehearsal succeeds.
